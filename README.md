# 동네지수

VS Code에서 이 폴더를 열고 터미널에서 아래 명령을 실행합니다.

```text
npm run dev
```

브라우저에서 `http://localhost:5173`을 열면 실행됩니다.

## 공공데이터 API 설정

1. [공공데이터포털](https://www.data.go.kr/data/15013117/standard.do)에서 `전국공공시설개방정보표준데이터`를 활용신청합니다.
2. `.env.example` 파일을 복사해 이름을 `.env`로 바꿉니다.
3. `.env`의 `DATA_GO_KR_SERVICE_KEY`에 발급받은 **일반 인증키(Decoding)**를 입력합니다.
4. `npm run dev`로 서버를 다시 시작합니다.

인증키는 `index.html`에 넣지 않습니다. 서버의 `/api/public-facilities?region=해운대구` 경로가 공공시설 개방정보를 불러옵니다.

## 카카오 지도 설정

`.env`의 `KAKAO_JAVASCRIPT_KEY`에 카카오디벨로퍼스의 **JavaScript 키**를 넣습니다. 카카오디벨로퍼스 앱 설정의 `플랫폼 > Web`에는 개발 주소인 `http://localhost:5173`을 등록합니다. 포트가 변경되면 실행 중인 주소도 함께 등록합니다.

## 전국 평균 최초 설정

1. `npm run benchmark:prepare`로 공식 읍면동 목록을 준비합니다(이미 준비된 목록은 유지).
2. 서버 실행 후 `http://localhost:5173/benchmark-setup.html`을 엽니다.
3. 반경을 선택하고 **최초 집계 시작 / 이어하기**를 누릅니다. 브라우저와 서버를 열어 둡니다.
4. 완료된 동은 즉시 `data/benchmark-1000.json` 등 반경별 파일에 저장됩니다. 중지·브라우저 재실행 후 이어하기가 가능합니다.
5. 모든 동의 조회가 완료되면 분석 화면을 새로고침합니다. 이후에는 저장된 기준만 읽고 전국 장소 재조회는 하지 않습니다.

계산: 같은 반경의 완료된 읍면동 대표 위치별 시설 수를 모두 더한 뒤 완료 표본 수로 나눕니다. 읍면동별 동일 가중이며 인구 가중 평균이나 시 평균의 평균이 아닙니다. 공원은 개수만 점수에 반영합니다. 센터 주변 표본 기준이지 동 전체 개수나 모든 주소의 평균은 아닙니다.

원본: [행정안전부_읍면동 하부행정기관 현황](https://www.data.go.kr/data/15059715/fileData.do). 2025-12-31 자료의 3,556개 사무소 행을 동일 지역·읍면동 키로 중복 제거했습니다. 대표 위치는 사무소 주소를 카카오로 변환합니다. 현재 준비 목록은 3,555개 대표 위치/229개 시군구입니다.

조회 실패·카카오 검색 한도 초과는 저장하지 않고 재시도합니다. 실제 성공한 검색의 0개만 0으로 반영하며, 미완료 전국 평균은 공개하지 않습니다. 공공데이터와 카카오 등록 정보는 현실의 모든 시설을 보장하지 않으며, 제공기관 누락까지 자동 판별할 수는 없습니다. 최초 전국 조회는 수만 회 이상의 요청이 발생할 수 있고 사용량 제한으로 며칠에 걸쳐 이어하기가 필요할 수 있습니다.

기준값은 자동 갱신하지 않습니다. 데이터가 바뀌면 기존 집계 파일을 별도 보관한 뒤 다시 집계해야 합니다. 데이터 버전/반경별로 기준을 분리합니다. 같은 반경의 겹치는 표본에 동일 시설이 포함되는 것은 각 위치의 접근성을 측정하기 위한 의도된 계산입니다.

## GitHub + Render 배포

이 폴더 자체를 GitHub 저장소의 최상위로 올리는 구성을 권장합니다. GitHub Pages가 아닌 Node 서버가 필요한 프로젝트입니다.

1. `.env`는 올리지 않습니다. `data/crime.csv`, `data/cctv.csv`, `data/benchmark-locations.json`, `data/benchmark-1000.json`은 함께 올립니다. CSV는 공공데이터 원본이며 개인 자료는 추가하지 않습니다.
2. Render에서 **New → Blueprint**를 선택하고 해당 저장소를 연결합니다. 최상위 `render.yaml`을 사용합니다.
3. `DATA_GO_KR_SERVICE_KEY`와 `KAKAO_JAVASCRIPT_KEY`에 기존 키를 직접 입력합니다. 키를 README나 GitHub 코드에 적지 않습니다.
4. 수동으로 **Web Service**를 생성할 경우 Node 환경, Build `npm install`, Start `npm start`, 환경변수 `NODE_ENV=production`과 위 두 키를 설정합니다. 저장소 최상위가 이 폴더이면 Root Directory는 비웁니다.
5. 발급된 HTTPS 주소를 카카오 개발자 사이트의 JavaScript SDK 도메인에 추가합니다. localhost 도메인은 개발용으로 유지할 수 있습니다.
6. 새 주소에서 주소 검색, 지도 표시, 시설 개수, 두 지역 비교, 1km 평균과 점수를 확인합니다. 다른 반경의 평균은 해당 반경의 사전 집계 파일이 있어야 합니다.

CSV 경로를 지정하지 않으면 프로젝트 안의 두 CSV를 사용합니다. 로컬 `.env`에 설정한 다운로드 폴더 경로는 Render에 복사하지 마세요.

배포 서버에서는 평균 설정 변경 API를 차단합니다. 확정한 평균을 갱신하려면 로컬에서 계산한 파일을 GitHub에 반영해 다시 배포합니다. 무료 Render 서버는 유휴 시 중단되고 재접속 시 시작 시간이 필요하며, 실행 중 저장한 파일은 영구 보관되지 않습니다. 기존 저장소에 포함한 평균 파일은 배포 시 다시 제공됩니다.

공식 안내: https://render.com/docs/web-services / https://render.com/docs/free / https://apis.map.kakao.com/web/guide/
